# 我的前端工程化清单：从混乱到可维护

一些已经验证过的工作流选择。不是最佳实践，而是适合长期独立创作的低摩擦系统。

## 先让结构清楚

一个项目至少要让人一眼知道入口在哪里、页面在哪里、样式和脚本在哪里。清晰的目录结构会降低每一次修改的心理成本。

```text
project/
├── index.html
├── html/
├── css/
├── js/
└── markdown/
```

结构不是仪式感，而是给未来的自己留下的导航。
